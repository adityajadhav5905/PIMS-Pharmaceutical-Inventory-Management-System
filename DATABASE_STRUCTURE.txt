│ 3.4 TRANSACTIONS COLLECTION
├─────────────────────────────────────────────────────────────────────────────┤

Collection Name: transactions
Purpose: Records all stock movements (purchases/restocks and sales)
Indexes: createdAt (descending)
Relations: References Medicine and Inventory collections
Document Comments: Stock movement — IN (purchase/restock) or OUT (sale). 
                    Financial fields set on OUT.

Document Structure:
{
  _id: ObjectId,
  medicine: ObjectId (ref: "Medicine", required),
  inventory: ObjectId (ref: "Inventory"),
  quantity: Number (required, min: 1),
  type: String (enum: ["IN", "OUT"], required),
  unitBuyPrice: Number (default: 0),
  unitSellPrice: Number (default: 0),
  totalCost: Number (default: 0),
  totalRevenue: Number (default: 0),
  profit: Number (default: 0),
  note: String,
  createdAt: Date (auto-generated),
  updatedAt: Date (auto-generated)
}

Field Descriptions:
  _id              - MongoDB ObjectId, unique identifier
  medicine         - Reference to Medicine document
  inventory        - Reference to Inventory batch document
  quantity         - Number of units in transaction
  type             - IN (purchase) or OUT (sale)
  unitBuyPrice     - Cost price per unit at transaction time
  unitSellPrice    - Sale price per unit at transaction time
  totalCost        - quantity * unitBuyPrice (for IN transactions)
  totalRevenue     - quantity * unitSellPrice (for OUT transactions)
  profit           - totalRevenue - totalCost (only for OUT transactions)
  note             - Transaction notes/reason (e.g., "Ward issue", "Restock")
  createdAt        - Timestamp of transaction
  updatedAt        - Timestamp of last modification

Transaction Types:
  IN Type:
    - Incoming stock from supplier
    - totalCost = quantity * unitBuyPrice
    - totalRevenue = 0
    - profit = 0
    - Note examples: "Initial stock", "Stock added", "Purchase"

  OUT Type:
    - Sales/usage from inventory
    - totalCost = quantity * unitBuyPrice
    - totalRevenue = quantity * unitSellPrice
    - profit = totalRevenue - totalCost
    - Note examples: "Ward issue", "Sale", "Usage"

4. DATABASE INDEXES

The following indexes are created for performance optimization:

  - Index 1: { name: 1 } - Search by medicine name

  - Index 2: { currentStock: 1 } - Find low/high stock levels

  - Index 1: { createdAt: -1 } - Sort transactions by date

Collection: alerts
  - Index 1: { createdAt: -1 } - Sort alerts by date

Collection: users
  - Implicit Index: { email: 1 } - Created due to unique constraint

Collection: staff
  - Implicit Index: { email: 1 } - Created due to unique constraint

Unique Constraints:
  - users: email
  - medicines: sku
  - staff: email

5. DOCUMENT RELATIONSHIPS & REFERENCES
================================================================================

Relationship Diagram:

medicines (1) ←─── (many) inventories
    │                        │
    │                        │
    ├────→ (1 purchase) transactions ←── (1) users (closedBy)
    │
    └────→ (1) predictions


inventories (1) ←─── (many) alerts
    │
    └────→ (1 user via closedBy in alerts)

Detailed Relationships:

1. medicines → inventories
   Type: One-to-Many (1:N)
   Field: inventories.medicine = medicines._id
   Meaning: One medicine can have multiple batch records in inventory

2. medicines → transactions
   Type: One-to-Many (1:N)
   Field: transactions.medicine = medicines._id
   Meaning: One medicine can have multiple transaction records

3. medicines → predictions
   Type: One-to-Many (1:N)
   Field: predictions.medicine = medicines._id
   Meaning: One medicine can have multiple prediction records

4. inventories → transactions
   Type: One-to-Many (1:N)
   Field: transactions.inventory = inventories._id
   Meaning: One inventory batch can have multiple transactions

5. inventories → alerts
   Type: One-to-Many (1:N)
   Field: alerts.inventory = inventories._id
   Meaning: One inventory record can generate multiple alerts

6. users → alerts
   Type: One-to-Many (1:N)
   Field: alerts.closedBy = users._id
   Meaning: One user can close multiple alerts

6. DATA FLOW & BUSINESS LOGIC
================================================================================

Stock Management Flow:
  1. Add Medicine (medicines collection)
  2. Create Inventory Batch (inventories collection)
  3. Record Stock IN Transaction (transactions collection)
  4. System monitors stock levels
  5. If currentStock <= reorderLevel → Generate LOW_STOCK alert
  6. When stock is sold → Record OUT Transaction
  7. Update inventory.currentStock
  8. Calculate profit = totalRevenue - totalCost

Financial Calculation:
  - All sales (OUT transactions) calculate profit
  - profit = (quantity × unitSellPrice) - (quantity × unitBuyPrice)
  - Used in financial reports and staff performance tracking

Prediction Flow:
  1. ML service analyzes historical transaction data
  2. Generates demand predictions for medicines
  3. Stores predictions in predictions collection
  4. System uses predictions for inventory planning

Alert Generation:
  - LOW_STOCK: Triggered when inventory.currentStock <= inventory.reorderLevel
  - EXPIRY_WARNING: Triggered when expiryDate is within 30 days
  - OVERSTOCK: Triggered when stock exceeds safe levels
  - Severity assigned based on alert type and urgency

11. COMMON QUERIES & OPERATIONS

Find Low Stock Items:
  db.inventories.find({ $expr: { $lte: ["$currentStock", "$reorderLevel"] } })

Get Profit Report:
  db.transactions.aggregate([
    { $match: { type: "OUT" } },
    { $group: { _id: "$medicine", totalProfit: { $sum: "$profit" } } }
  ])

Get Pending Alerts:
  db.alerts.find({ isResolved: false }).sort({ createdAt: -1 })

Get Expiring Medicines (30 days):
  db.inventories.find({
    expiryDate: { $gte: new Date(), $lte: new Date(Date.now() + 30*24*60*60*1000) }
  })

Get Monthly Sales by Staff:
  db.transactions.aggregate([
    { $match: { type: "OUT", createdAt: { $gte: startOfMonth } } },
    { $group: { _id: "$staff", totalRevenue: { $sum: "$totalRevenue" } } }
  ])

1. MongoDB Atlas Account

2. MongoDB Cluster Created
   - Create a new cluster in Atlas
   - Choose your cloud provider (AWS, GCP, Azure)
   - Choose a region close to you
   - Select cluster tier (M0 Free tier recommended for dev)

3. Database User Created
   - Go to Database Access in Atlas
   - Create a new database user
   - Note username and password (you'll need these)
   - Grant atlasAdmin role or custom role with read/write access

4. Network Access Allowed
   - Go to Network Access in Atlas
   - Add your IP address (or 0.0.0.0/0 for development)
   - Current IP: Available in Atlas console

─────────────────────────────────────────────────────────────────────────────
12.2 GET YOUR CONNECTION STRING
─────────────────────────────────────────────────────────────────────────────

Step 1: Go to Your Cluster
  - Click "Connect" button on your cluster
  - Choose "Connect your application"
  - Select "Node.js" driver

Step 2: Copy Connection String
  Example format:
  mongodb+srv://<username>:<password>@<cluster>.mongodb.net/<database>?retryWrites=true&w=majority

  Actual example:
  mongodb+srv://admin:MyPassword123@mycluster.abcdefg.mongodb.net/medical_inventory?retryWrites=true&w=majority

Step 3: Replace Placeholders
  - Replace <username> with your database user
  - Replace <password> with your user password (URL encode special chars)
  - Replace <cluster> with your cluster name
  - Replace <database> with "medical_inventory"

URL Encoding Special Characters in Password:
  - @ symbol → %40
  - # symbol → %23
  - : symbol → %3A
  - ! symbol → %21
  Example: Pass@123 → Pass%40123

```javascript
    await mongoose.connect(env.mongoUri, {
      useNewUrlParser: true,
      useUnifiedTopology: true,
      maxPoolSize: 10,
      minPoolSize: 2,
      retryWrites: true
    });
    console.log("✓ Connected to MongoDB Atlas");
  } catch (error) {
    console.error("✗ MongoDB connection failed:", error.message);
    throw error;
  }
};
```

12.6 CONNECTION TROUBLESHOOTING
─────────────────────────────────────────────────────────────────────────────

Error: "connection refused"
  Solution: Check if your IP is whitelisted in Network Access
  - Add your IP: 0.0.0.0/0 (allows all) - for development only
  - For production: Add specific IP addresses

Error: "Authentication failed"
  Solution: Verify username, password, and database name
  - Check credentials in MongoDB Atlas > Database Access
  - Verify password doesn't have special characters
  - If it does, URL encode them (%40 for @, etc.)

Error: "Certificate validation failed"
  Solution: Add SSL certificate option
  ```javascript
  await mongoose.connect(uri, {
    tls: true,
    tlsInsecure: false  // Set to true only for testing
  });
  ```

Error: "timeout connecting to server"
  Solution: Check network connectivity
  - Ensure firewall allows MongoDB port 27017
  - For Atlas, this is handled automatically
  - Try pinging the hostname

Error: "getaddrinfo ENOTFOUND"
  Solution: DNS resolution issue
  - Check internet connection
  - Try using IP instead of hostname temporarily
  - Restart application

Testing Connection:
  1. Create test file: test-connection.js
  
  ```javascript
  import mongoose from "mongoose";
  
  const mongoUri = process.env.MONGO_URI;
  
  mongoose.connect(mongoUri).then(() => {
    console.log("✓ Successfully connected to MongoDB Atlas");
    process.exit(0);
  }).catch(error => {
    console.error("✗ Connection failed:", error);
    process.exit(1);
  });
  ```
  
  2. Run: node test-connection.js

  5. Archive old data regularly

Backup Strategy:
  1. Enable continuous backups in Atlas
  2. Automated backups retention: 35 days (default)

  4. Manual snapshots for critical releases

Monitoring:
  1. Use MongoDB Atlas monitoring dashboard
  2. Set up alerts for:
     - CPU usage > 80%
     - Memory usage > 80%
     - Connection count > threshold
     - Slow queries (> 1000ms)

  1. M0 free cluster: 512MB storage

  4. Limited monitoring
